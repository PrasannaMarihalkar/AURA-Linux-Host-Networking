## 2. Contract Specifications and Boundary Enforcement

### 2.1 Ingress vs Ingested Client Window
- **Ingress (`client_window.schema.json`):** Generated by the client. Contains client-observed timing, request counts, throughput, and percentiles. Severely rejects server-owned fields (`server_received_timestamp_utc`, `server_boot_id`, `client_ip`).
- **Ingested (`client_window_ingested.schema.json`):** Created atomically by the server upon successful ingress validation. Stamps server monotonic time, UTC timestamp, boot ID, and client remote address.

### 2.2 Host Telemetry (`host_snapshot.schema.json`)
- Captures system and per-CPU state over discrete windows.
- Invariants:
  - System CPU PSI `full` is completely omitted (`docs/accounting/psi.html`).
  - CPU hotplug dynamic sets are preserved.
  - Counter wraps or resets are explicitly flagged with `reason: counter_reset`.
  - Missing metrics return `status: unavailable` without fabricating 0.

### 2.3 Controller Events & Action Records (`controller_event.schema.json`, `action_record.schema.json`)
- Every diagnosis decision generates a structured controller event containing:
  - `tail_health`: `nominal`, `degraded_p99`, `degraded_p999`, `degraded_both`.
  - `p99_status` / `p999_status`: `sufficient` vs `insufficient`.
  - `diagnosis`: Candidate root cause (e.g. `cpu_contention_candidate`, `softnet_backlog_candidate`, `rx_imbalance_candidate`, `nominal`, `uncertain`).
  - `action`: In Gate B observe-only mode, strictly `no_op`.
  - `action_record`: Null in Gate B; populated in Gate C with dry-run or applied execution status, target, previous value, new value, and rollback details.

### Isolation Invariants
1. **Controller Isolation:** `aura.controller` and `aura.diagnosis` **never import or invoke** `aura.controls`. A dedicated unit test in `tests/test_controls.py` (`test_controller_never_imports_or_calls_controls`) dynamically inspects controller modules to prevent architectural leakage.
2. **Observe-Only Mode:** In Gate B, controller action must be `no_op` with `execution_status: not_attempted` or `dry_run`. Applying actions in observe-only mode triggers schema and runtime assertion errors.
3. **Controlled Gate C Entry:** `aura/controls/cgroup_cpu.py` and `aura/controls/rpsctl.py` are isolated support libraries intended exclusively for standalone actuation scripts (`scripts/setup_slices.sh`, `scripts/restore.sh`) and future Gate C integration.

## 4. Invariant Validation, Error Handling, and Recovery Strategies

| Failure Domain | Error Condition | Subsystem Response | Recovery / Fallback Strategy |
| :--- | :--- | :--- | :--- |
| **Benchmark Delivery** | Server HTTP 503 or transient network refusal | Benchmark client async delivery worker | Exponential backoff (50ms, 100ms), up to 2 retries; logged to local client sidecar if unreachable. |
| **Ingestion Concurrency** | Identical `(run_id, window_id)` posted concurrently | Server ingestion handler | In-flight event synchronization under `dedup_lock`; returns idempotent HTTP 200 without duplicate disk write. |
| **Queue Saturation** | Ingestion bursts exceeding runtime worker capacity | Server ingestion handoff | Server returns HTTP 503 (`runtime_backpressure`), preserving queue integrity and shedding load. |
| **Statistical Sufficiency** | Window sample count $N < 100$ for P99 | Diagnosis engine | Forces `p99_status = insufficient`, `diagnosis = uncertain`, `action = no_op`; avoids false positive actuation. |
| **Cgroup Control Failure** | Post-write readback value does not match target | Cgroup CPU weight controller | Immediately writes back previous baseline value (rollback); logs `verification_failed_rolled_back`. |
| **Linux Telemetry Rollover** | Interface byte/packet counter wraps 32/64-bit | Telemetry delta calculator | Detects negative delta, marks delta as `null`, sets `reason = counter_reset`, resets baseline cleanly. |
